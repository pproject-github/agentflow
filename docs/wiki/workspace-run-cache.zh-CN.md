# 运行缓存：从「有值就算数」到指纹

## 症状

```
a 的脚本是 echo one  → 运行 → b 拿到 'one'
把 a 改成 echo two   → 运行 → a 根本不跑，b 还是拿到 'one'
```

只影响**不在控制链上、靠数据边被拉进计划**的节点。`flow("Run", b)` 里只有 `b`，`a` 是被
`b` 正文里的 `${got}` 拉进来的。

第一次跑完 `a.result` 槽有了值，之后判定一律命中——它只看槽里有没有值，不看 `a` 自己变没变。

落到内置模板上：

| 流程 | 数据边上游 | 改了它再点② |
|---|---|---|
| `new` / buildRun | `skills`、`plan` | 改规划的提示词 → 还是照旧方案落地 |
| `module-migrate` / migrateRun | `scope` | 改定范围的提示词 → 还是用旧清单迁移 |

逃生口只有一个：手动删掉 `outputs/<node>/` 下的文件。

## 不是人工闸门的问题

`flow.resume` 那套是对的。点②不重跑 `plan` 正是想要的语义——②就是「照确认过的方案落地」。
要重新规划就点①，`plan` 在①的控制链上，必跑。实测确认过：闸门确认的值不会被覆盖。

## 判据：加一道指纹

命中条件从「槽里有值」改成「槽里有值 **且** 这套输入的指纹和上次成功执行时记录的一致」。

```
fp(node) = sha256(
  definitionId, body, scriptRef, marketplaceRef, script, model,
  每个输入槽:  接了线 → `槽名<=源节点.源槽:fp(源节点)`
              没接线 → `槽名=字面值`
)
```

**上游用指纹参与哈希，不用值。** 两个好处：不必读大文件；上游一变下游自动跟着变，脏传播是
算出来的，不用再写一遍传播逻辑。

### 三样东西不进指纹

- **输出槽的值。** 指纹描述输入，不描述产出。agent 节点同样输入重跑本来就给不同结果，把
  产出算进去等于永远不命中。
- **`marketplaceRef` 推导出来的 `script`。** 那串里带着本机绝对路径（`node '/Users/…/index.mjs'`），
  算进去就换台机器全部失效。改用 `marketplaceRef` 本身，包版本一升照样失效。
- **run 级别的 model。** 它是一次运行的旋钮，不是节点的属性。算进去等于换个模型就把整张图
  的缓存推倒。节点自己写死的 model 覆盖仍然计入。

### 两个不吃指纹的例外

- **`provide.*`** 不执行，值是作者填的，没有「上次跑出来的」这回事——照旧只看有没有值
- **产出文件不存在**时不算命中，指纹对得上也不行（`outputs/…` 路径要真有那个文件）

## 为什么不照搬 React

React 里对应的是 `useMemo(fn, [deps])` 加 bailout，这一半正是我们要的。另外两半借不了：

- **虚拟树。** reconciliation 解决的是「结构要 render 出来才知道，所以得 diff 新旧树」。
  我们的结构就是磁盘上的 `workspace.flow.js`，显式、持久、可直接比对。造一棵影子树去 diff
  一个已知结构是白搭一层。
- **引用相等。** `Object.is` 成立的前提是一次 render 在一个进程里，对象身份稳定。我们的值
  跨进程、跨重启、跨机器落盘，没有身份可比，只能比内容。

还有一个 React 依赖、我们没有的前提：**render 是纯的**，跳过重算和重算结果一样。agent 节点
不纯。所以缓存在这里不只是省钱——点②之所以能照着你确认的方案落地，就是因为 `plan` 命中了
缓存。方向不是把缓存收紧，是让它判得准。

真正对得上的参照是 Bazel / Nix / Turborepo / Salsa 那套内容寻址构建图。

## 存在哪

`runFingerprint` 是**实例级的运行态字段**，和 `displayReloadKey` 同一条路：

```
splitWorkspaceGraph    instance.runFingerprint  →  state.fingerprints[nodeId]
mergeWorkspaceState    反向合回来
isRuntimePath          冲突时算运行态，不拦用户
```

因此它不进 `workspace.flow.js`，不污染 diff，也**不改变 `designRevision`**——跑一次就让
协作者手里的基线作废，是这套设计最容易犯的错，有断言守着。

判定以磁盘为准：`hydrateWorkspaceGraphForRuntime`（计划和运行的唯一收口）用
`readWorkspaceRunFingerprints` 覆盖图里的指纹字段。客户端提交的那份一律不作数——否则「这个
值是不是真跑出来的」就成了调用方说了算，手填一个值就能整段跳过执行。

覆盖而不是补齐：磁盘上没记录的节点把字段抹掉，判定落到重跑那边。老流程升级上来没有指纹，
第一次运行会重算一遍，这是安全方向。

## 强制重跑是必要配套，不是附加功能

节点会读仓库、读网络、读环境变量——这些外部状态进不了指纹，所以缓存**一定会有判错的时候**。
Bazel 靠沙箱回避，我们回避不了。

两个粒度：

| 入口 | 效果 |
|---|---|
| run 节点上的 `restart_alt` 按钮 / 请求体 `ignoreCache: true` | 整张图不吃缓存 |
| 请求体 `forceNodeIds: [...]` | 指定节点不吃缓存 |
| 节点卡片上原有的「清理输出」 | 删掉产出文件，等价于让该节点失效 |

`ignoreCache` 不能用「`forceNodeIds` 填上所有节点」代替：能填进去的只有计划里已有的节点，
而被缓存挡掉的那些恰恰不在计划里。

## 守住

`test/workspace-run-cache.test.mjs`，13 条。关键几条：

1. 改自己的脚本 → 指纹变
2. 只改上游 → 下游指纹跟着变（脏传播是算出来的）
3. 改产出 → 指纹不变（否则 agent 节点永远不命中）
4. 推导脚本里的本机路径不影响指纹，包版本变了则失效
5. 改了上游的脚本 → 上游重跑（就是开头那个 bug；变异测试确认这条会咬）
6. 没有指纹记录 → 重跑
7. 指纹对得上但产出文件没了 → 重跑
8. `designRevision` 不因指纹变化
